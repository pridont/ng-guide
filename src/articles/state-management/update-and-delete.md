# წაშლა და მონიშვნა

ახლა ისღა დაგვრჩენია, რომ შევძლოთ ნივთების დასრულებულად მონიშვნა და წაშლა.
სერვისში დავამატოთ მათი მეთოდები `deleteItem` და `updateItem`:

```ts
  deleteItem(id: number) {
    this.request(this.http.delete<void>(`${this.url}/${id}`), () => {
      this._todos.update((todos) => todos.filter((item) => item.id !== id));
    });
  }

  updateItem(updatedItem: TodoItem) {
    this.request(
      this.http.patch<TodoItem>(`${this.url}/${updatedItem.id}`, updatedItem),
      (item) => {
        this._todos.update((todos) =>
          todos.map((todo) => (todo.id === item.id ? item : todo))
        );
      }
    );
  }
```

აქ კარგად ჩანს, რატომ ღირდა [წინა თავში](./loading-state-and-error.html)
`request` მეთოდის გამოყოფა: ორივე ახალი მეთოდი ორ-სამ ხაზში ჩაეტია.
`loading`-ისა და ერორის ლოგიკა ავტომატურად მოყვათ.

`deleteItem`-ში წასაშლელი ნივთის აიდის მივიღებთ პარამეტრში და გავგზავნით
DELETE მოთხოვნას ამ აიდის ენდფოინთზე. საპასუხოდ მონაცემი არ გვიბრუნდება
(ამიტომ `delete<void>` და ქოლბექში პარამეტრი არ გვაქვს), თუმცა HTTP
მოთხოვნის წარმატების შემთხვევაში ქოლბექი მაინც გააქტიურდება. ჩვენ წაშლილი
ნივთის აიდის მიხედვით ვფილტრავთ არსებულ მასივს, რათა ის წაშლილ ნივთს არ
შეიცავდეს.

`updateItem`-ში პარამეტრად ვიღებთ თვითონ განახლებულ ნივთს და მას გადავცემთ
PATCH მოთხოვნას ამ ნივთის აიდის მქონე ენდფოინთზე. ეს მოთხოვნა აბრუნებს
განახლებული ნივთის ობიექტს, რომელსაც ჩვენ ქოლბექში ვიღებთ და საპასუხოდ
`map`-ით ვქმნით განახლებულ სიას, სადაც აიდით ვპოულობთ იმ ძველ ნივთს,
რომელიც ბექენდში განვაახლეთ, და მას ვანაცვლებთ ახალი ნივთით.

გაითვალისწინეთ, რომ `filter` და `map` **ახალ მასივს აბრუნებენ** — სწორედ
ისე, როგორც სიგნალს სჭირდება. ეს შემთხვევითი არ არის: ჯავასკრიპტის
უცვლელი (immutable) მეთოდები და სიგნალები ერთმანეთს კარგად ერგება.

## კომპონენტში

შევქმნათ სათანადო მეთოდები მათ დასაძახებლად:

```ts
  changeDone(itemToChange: TodoItem) {
    this.todoService.updateItem({
      ...itemToChange,
      done: !itemToChange.done,
    });
  }

  deleteItem(id: number) {
    this.todoService.deleteItem(id);
  }
```

როცა ნივთს მოვნიშნავთ, ჩვენ პარამეტრში მივიღებთ სამიზნე ობიექტს და მას
შევუცვლით `done` თვისებას არსებულის საპირისპიროთი. აქაც ახალ ობიექტს
ვქმნით სპრედ ოპერატორით, და არა თავდაპირველს ვცვლით. შემდეგ ამ ობიექტს
გავატანთ სერვისის მეთოდს.

წაშლის შემთხვევაში პირდაპირ აიდის მივიღებთ პარამეტრში, რომელსაც მეთოდს გავატანთ.

სადაც თითოეულ ნივთს ვარენდერებთ `@for` ბლოკით, შემდეგი ცვლილებები შეგვაქვს:

```html
@for (item of todoService.todos(); track item.id) {
  <li class="list-group-item d-flex justify-content-between align-items-center">
    <div class="d-flex align-items-center">
      <input type="checkbox" [checked]="item.done" (click)="changeDone(item)" />
      <span class="ms-2">{{ item.title }}</span>
    </div>
    <button class="btn btn-danger" (click)="deleteItem(item.id)">
      <svg
        xmlns="http://www.w3.org/2000/svg"
        width="16"
        height="16"
        fill="currentColor"
        class="bi bi-trash3-fill"
        viewBox="0 0 16 16"
      >
        <path
          d="M11 1.5v1h3.5a.5.5 0 0 1 0 1h-.538l-.853 10.66A2 2 0 0 1 11.115 16h-6.23a2 2 0 0 1-1.994-1.84L2.038 3.5H1.5a.5.5 0 0 1 0-1H5v-1A1.5 1.5 0 0 1 6.5 0h3A1.5 1.5 0 0 1 11 1.5Zm-5 0v1h4v-1a.5.5 0 0 0-.5-.5h-3a.5.5 0 0 0-.5.5ZM4.5 5.029l.5 8.5a.5.5 0 1 0 .998-.06l-.5-8.5a.5.5 0 1 0-.998.06Zm6.53-.528a.5.5 0 0 0-.528.47l-.5 8.5a.5.5 0 0 0 .998.058l.5-8.5a.5.5 0 0 0-.47-.528ZM8 4.5a.5.5 0 0 0-.5.5v8.5a.5.5 0 0 0 1 0V5a.5.5 0 0 0-.5-.5Z"
        />
      </svg>
    </button>
  </li>
}
```

`input`-ზე ვამატებთ დაკლიკების ივენთ ბაინდინგს, რომელსაც ვაკავშირებთ `changeDone`
ფუნქციასთან და მას არგუმენტად ვაწვდით მთლიან ობიექტს.

გვერდით ვამატებთ წაშლის აიქონიან ღილაკს, რომელსაც ივენთ ბაინდინგით ვაკავშირებთ
`deleteItem` მეთოდთან და მას ვაწვდით ნივთის აიდის.

`track item.id` აქ განსაკუთრებით მნიშვნელოვანია: სწორედ ის ეუბნება ანგულარს,
რომელი `li` ელემენტი რომელ ნივთს შეესაბამება. წაშლისას ეს იმას ნიშნავს, რომ
DOM-იდან **მხოლოდ ერთი** ელემენტი წაიშლება, და არა მთელი სია არ გადარენდერდება.

ახლა ჩვენი აპლიკაცია სრულფასოვნად უნდა მუშაობდეს. უნდა შესაძლებელი იყოს:

- არსებული ნივთების ნახვა
- ახალი ნივთის დამატება
- ნივთის წაშლა
- ნივთის მონიშვნა
- ყოველი მოთხოვნის გაგზავნის დროს სპინერის გამოჩენა
- ერორის შემთხვევაში ერორის მესიჯის გამოჩენა

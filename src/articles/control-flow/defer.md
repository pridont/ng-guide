# `@defer` — ზარმაცი ჩატვირთვა

აპლიკაციის ყველა ნაწილი თანაბრად მნიშვნელოვანი არ არის. გვერდის თავში
არსებული სათაური მომხმარებელს მაშინვე სჭირდება, ხოლო გვერდის ბოლოში
არსებული კომენტარების სექცია — შესაძლოა საერთოდ არასდროს.

მიუხედავად ამისა, ჩვეულებრივ **მთელი კოდი ერთად ჩამოიტვირთება**. რაც უფრო
დიდია აპლიკაცია, მით უფრო დიდხანს ელოდება მომხმარებელი პირველი ეკრანის
დანახვას.

[Lazy-loading-ს](/standalone/routing-and-lazy-loading.html) როუთინგის
დონეზე უკვე შევხვდით. `@defer` იმავე იდეას **თემფლეითის დონეზე** გვაძლევს:

```html
@defer {
  <app-comments />
}
```

ეს იმას ნიშნავს, რომ `Comments` კომპონენტის (და მისი დირექტივების, ფაიფების,
სტილების) კოდი **ცალკე JavaScript ფაილში გამოიყოფა** და მხოლოდ მაშინ
ჩამოიტვირთება, როცა საჭირო გახდება. აპლიკაციის საწყისი ბანდლი პატარავდება.

## რა შეიძლება გადაიდოს

`@defer` ბლოკის შიგნით არსებული დამოკიდებულებები ორ პირობას უნდა აკმაყოფილებდეს:

1. **უნდა იყოს standalone.** `NgModule`-ში გამოცხადებული კომპონენტები
   ვერ გადაიდება და მაინც მაშინვე ჩამოიტვირთება.
2. **არ უნდა იყოს გამოყენებული `@defer` ბლოკის გარეთ, იმავე ფაილში.**
   თუ იმავე თემფლეითში კომპონენტი სხვაგანაც გვხვდება (ან `viewChild`
   query-ში), მაშინ მისი გადადება აზრს კარგავს და ანგულარი მას მაინც
   მაშინვე ჩატვირთავს.

ეს მეორე პირობა ხშირად უცნაურ სიურპრიზს ქმნის: `@defer` დაწერილია, მაგრამ
ბანდლი არ პატარავდება. მიზეზი თითქმის ყოველთვის ისაა, რომ იგივე კომპონენტი
სადმე კიდევ არის ნახსენები.

## დამატებითი ბლოკები

`@defer`-ს რამდენიმე დამხმარე ბლოკი აქვს, რომლებიც ჩატვირთვის სხვადასხვა
ეტაპს ფარავს.

### `@placeholder`

ნაგულისხმევად `@defer` ბლოკი გააქტიურებამდე **არაფერს** არენდერებს.
`@placeholder` განსაზღვრავს, რა გამოჩნდეს მანამდე:

```html
@defer {
  <app-comments />
} @placeholder {
  <p>Comments will load shortly...</p>
}
```

`@placeholder`-ს არასავალდებულო პარამეტრი `minimum` აქვს — მინიმალური დრო,
რამდენ ხანსაც უნდა გამოჩნდეს. ეს იმისთვისაა, რომ სწრაფი ჩატვირთვისას
შიგთავსმა არ "აციმციმდეს":

```html
@defer {
  <app-comments />
} @placeholder (minimum 500ms) {
  <p>Comments will load shortly...</p>
}
```

### `@loading`

`@loading` ჩანაცვლდება `@placeholder`-ს იმ მომენტში, როცა ჩატვირთვა
რეალურად დაიწყო:

```html
@defer {
  <app-comments />
} @loading (after 100ms; minimum 1s) {
  <p>Loading...</p>
} @placeholder {
  <p>Comments will load shortly...</p>
}
```

ორი პარამეტრი აქვს:

- `after` — რამდენი ხნის შემდეგ გამოჩნდეს ჩატვირთვის ინდიკატორი. თუ
  ჩატვირთვა 100 მილიწამზე სწრაფად დასრულდა, ინდიკატორი საერთოდ არ გამოჩნდება
- `minimum` — მინიმალური დრო, რამდენ ხანსაც უნდა გამოჩნდეს

### `@error`

თუ ჩატვირთვა ჩავარდა (მაგალითად ინტერნეტი გაითიშა):

```html
@defer {
  <app-comments />
} @error {
  <p>Failed to load comments.</p>
}
```

**გასათვალისწინებელია:** `@placeholder`, `@loading` და `@error` ბლოკების
დამოკიდებულებები **მაშინვე ჩამოიტვირთება**. ამიტომ მათში მძიმე კომპონენტების
ჩასმა აზრს უკარგავს მთელ ამბავს — იქ მარტივი მარკაპი უნდა იყოს.

## ტრიგერები

ნაგულისხმევად `@defer` მაშინ აქტიურდება, როცა ბრაუზერი უსაქმური ხდება
(`on idle`). ეს ქცევა შეგვიძლია შევცვალოთ.

ტრიგერები ორი ტიპისაა: `on` და `when`.

### `on`

| ტრიგერი | როდის აქტიურდება |
|---|---|
| `idle` | ბრაუზერი უსაქმური ხდება (ნაგულისხმევი) |
| `viewport` | შიგთავსი ეკრანზე ჩნდება |
| `interaction` | მომხმარებელი ელემენტს დააკლიკებს ან კლავიშს დააჭერს |
| `hover` | მაუსი ელემენტზე გადადის |
| `immediate` | დანარჩენი შიგთავსის დარენდერებისთანავე |
| `timer(500ms)` | მითითებული დროის შემდეგ |

ყველაზე გამოსადეგი `viewport`-ია — შიგთავსი მაშინ ჩამოიტვირთება, როცა
მომხმარებელი მასთან მიაგორებს გვერდს:

```html
@defer (on viewport) {
  <app-comments />
} @placeholder {
  <div>Comments</div>
}
```

ნაგულისხმევად ანგულარი თვალს `@placeholder`-ს ადევნებს. ამიტომ ასეთ
შემთხვევაში `@placeholder` **სავალდებულოა** და მას **ერთი ძირეული
ელემენტი** უნდა ჰქონდეს.

ალტერნატიულად, თემფლეითის ცვლადით სხვა ელემენტიც შეგვიძლია მივუთითოთ:

```html
<div #greeting>Hello!</div>

@defer (on interaction(greeting)) {
  <app-greetings />
}
```

რამდენიმე ტრიგერის მითითება `;`-ით შეიძლება და ისინი **ან**-ის ლოგიკით
შეფასდება.

### `when`

`when` ჩვეულებრივ პირობას იღებს და მაშინ აქტიურდება, როცა ის ჭეშმარიტი გახდება:

```html
@defer (when showComments()) {
  <app-comments />
}
```

გაითვალისწინეთ, რომ `@defer` **ერთჯერადია**: თუ პირობა ისევ მცდარი გახდა,
შიგთავსი უკან აღარ იშლება.

## `prefetch` — წინასწარი ჩამოტვირთვა

ხშირად ვიცით, რომ მომხმარებელი რაღაცას *ალბათ* გამოიყენებს, თუმცა
დარწმუნებული არ ვართ. ასეთ დროს კოდის წინასწარ ჩამოტვირთვა შეგვიძლია, ისე
რომ ის ეკრანზე არ გამოჩნდეს:

```html
@defer (on interaction; prefetch on idle) {
  <app-comments />
} @placeholder {
  <div>Show comments</div>
}
```

აქ კოდი ჩამოიტვირთება მაშინ, როცა ბრაუზერი უსაქმური იქნება, ხოლო
დარენდერდება მხოლოდ მაშინ, როცა მომხმარებელი დააკლიკებს. შედეგად
დაკლიკებაზე შიგთავსი მომენტალურად გამოჩნდება.

## პრაქტიკული რჩევები

**ჩადგმული `@defer` ბლოკები ერიდეთ.** ერთი `@defer` მეორეში ჩატვირთვის
ჯაჭვს ქმნის: მეორე ბლოკი ვერ დაიწყებს ჩატვირთვას, სანამ პირველი არ
დასრულდება. შედეგად აპლიკაცია უფრო ნელი გამოდის, არა უფრო სწრაფი.

**გაითვალისწინეთ layout shift.** თუ `@placeholder` ბევრად პატარაა, ვიდრე
რეალური შიგთავსი, ჩატვირთვისას გვერდი "ახტება" და მომხმარებელი კითხვის
ადგილს კარგავს. ეს Core Web Vitals-ის ერთ-ერთ მაჩვენებელსაც (CLS) აფუჭებს.
placeholder-ს დაახლოებით იგივე ზომა უნდა ჰქონდეს.

**ყველაფერი არ უნდა გადაიდოს.** `@defer` საწყისი ეკრანისთვის საჭირო
შიგთავსზე მავნეა — ის ჩატვირთვას მხოლოდ აგვიანებს. ის იმისთვისაა, რაც
მომხმარებელს **მაშინვე არ სჭირდება**: მოდალები, კომენტარები, გრაფიკები,
გვერდის ქვედა ნაწილი.
